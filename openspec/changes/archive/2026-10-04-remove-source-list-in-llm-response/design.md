# Design

## Context

問題成因見 `proposal.md`，這裡只記修法的取捨。

RAG 回答中的「來源：」清單是 Gemini 依 `SYSTEM_PROMPT` 的「要標註引用的來源 (檔案名稱與章節)」自行生成的文字，頁面以 `st.markdown(answer)` 原樣渲染，程式本身沒有產生這段內容。同一份回應的來源另由 `_render_sources()` 從 `sources` 渲染成「📎 來源筆記」，這一份經過程式去重，並依登入角色決定是否顯示 vector 與 rerank 分數。因此要讓來源只出現一次，該拿掉的是模型生成的那一份。

模型之所以傾向列出來源，除了指令本身，還有兩個來源。其一是 `build_context()` 為每個 chunk 加上 `[來源 i] 檔案: ... | 章節: ...` 標頭，這個格式本身就在提示模型引用；其二是 chat_history 會把過去的回答原文帶回模型，舊回答裡的來源清單等同於示範。

## Goals / Non-Goals

**Goals:**

在新對話中，RAG 回答正文不再出現模型自行列出的來源清單，來源只透過「📎 來源筆記」呈現。改動範圍限定在 `SYSTEM_PROMPT` 字串，回答正文的其他指令（語氣、稱呼、資訊不足時的處理方式）維持原意。

**Non-Goals:**

本 change 不對模型回答做任何後處理，不修改 `build_context()` 的 context 格式，不清理 MongoDB 中既有的 chat_history，也不調整 `planning_agent` 的 prompt。

## Decisions

### 1. 只改 prompt，不以 regex 剝除回答結尾的來源段落

regex 後處理能保證來源清單一定不出現，也能讓寫進 chat_history 的內容保持乾淨，但它要比對的是模型自由生成的格式。模型可能寫「來源：」「參考來源」「出處」，也可能把來源放在段落中間而不是結尾，規則寫寬了會誤刪正文中剛好提到「來源」的句子，寫窄了又攔不到變體。相較之下，從指令端要求模型不要生成這段內容，改動最小，也不會誤傷正文。使用者已決定本 change 的範圍只到 prompt，若上線後觀察到模型仍常夾帶來源清單，再另開 change 評估後處理。

### 2. 明確禁止並說明理由，而不是只刪掉原本那句

如果只刪掉「要標註引用的來源」，模型仍會受 context 標頭與歷史回答的引導而列出來源。因此新指令要明確寫出「不要在回答中列出來源清單，也不要標註檔案名稱或章節」，並附上理由「系統會在回答下方另外顯示來源筆記」。讓模型知道這項資訊已有別處提供，比單純下禁令更容易被遵守。

預定的指令文字如下，取代原本第一條指令中「且要**標註引用的來源 (檔案名稱與章節)**。」這一句，並在其後新增一條：

```python
"- 回答時請使用繁體中文，語氣簡潔清楚，回答開頭直接描述找到的知識，稱呼使用者為**您**。"
"不用「根據你提供的筆記、根據資料庫」等這種客套用語作為開頭。\n"
"- 回答中不要列出「來源」清單，也不要標註檔案名稱或章節；系統會在回答下方另外顯示來源筆記。\n"
```

### 3. 保留 `build_context()` 的來源標頭

context 標頭雖然會提示模型引用，但它也是模型分辨各段文字出自哪份筆記的依據，拿掉會讓模型難以區分不同筆記的內容。此外 `build_context()` 由 RAG agent 與 Planning agent 共用，修改它會牽動 Planning agent 的行為，超出本 change 的範圍。指令層面的明確禁止已足以抵銷標頭的提示作用。

## Risks / Trade-offs

第一個風險是模型不保證每次遵守指令。`temperature=0.2` 已降低隨機性，但仍可能偶爾夾帶來源清單。本 change 接受這個風險，以上線後的實際觀察決定是否需要後處理。

第二個風險來自既有 session。MongoDB chat_history 中的舊回答仍含來源清單，會隨最近 3 輪歷史送回模型，讓舊 session 接下來數輪可能延續舊格式。新對話不受影響，使用者點側邊欄「🔄 開新對話」即可避開，因此不做資料清理。

第三個取捨是回答正文不再有任何來源標註。訪客與非訪客都能從「📎 來源筆記」看到檔名與章節，資訊沒有流失，只是不再於正文中逐句對應。

## Verification

LLM 輸出不具確定性，不適合以單元測試斷言回答內容，改以手動驗收：啟動 Streamlit，開新對話，提出幾個會命中同一章節多個 chunk 的查詢（例如先前出現重複的 MySQL Window Function），確認回答正文沒有「來源：」段落，且「📎 來源筆記」照常顯示，訪客角色看不到分數。

## Migration Plan

本 change 只修改一個字串常數，沒有資料遷移。部署方式與平常的 dashboard 更新相同，若需回滾，還原 `SYSTEM_PROMPT` 即可。
